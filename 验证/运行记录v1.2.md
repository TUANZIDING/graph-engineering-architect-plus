# 运行记录 v1.2（2026-11-15）

## 为什么升级
评测 v0.2（7 任务 × 有/无 Skill × 3 次）显示：
- 有 Skill 时结构缺陷从 15/15 降到 0/15，但两组在领域效度上都会漏（meta 分析偏倚/异质性审计：无 Skill 1/3，有 Skill 2/3）。
- 有一份有 Skill 的图（t9-r3）知道参照标准已 3 年，却没把“先复审”写成阻断，diagnose 只能报 at_risk。
- 评测提示里给 validate 传 `--today` 会报错（v1.1 只有 diagnose 接受）。

## 改了什么
1. **E-STALE**：锚点超过 max_age_days 时，必须由 `revalidation_gate` 人工门挡住它喂给的每个检查者；满足时 diagnose 状态为 `pending_revalidation`（不算失败，也不算健康）。
2. **E-DOMAIN / W-NODOMAIN**：`root_goal.domain` + `domain_audits`，把每个领域必需关注点钉到有否决权的检查节点（6 个领域，见 文档/领域效度清单v1.2.md）。
3. `validate` 接受 `--today`。
4. SKILL.md 设计流程新增第 7、8 步；schema_version 接受 1.2。

## 验证
- 回归测试 v1.0 21/21、v1.1 35/35、v1.2 44/44。
- 示例预期状态不变；v0.2 七份参照答案在 v1.2 下结果与 v1.1 相同。
- v0.2 有 Skill 的 t9-r3 在 v1.2 下由 at_risk 变为 blocked（E-STALE），符合预期。

## 尚未证明
领域清单是否真能让模型少漏检查，需要用**新任务**（不是 t7–t13）做 v0.3 对照评测；v1.2 的规则是看过 v0.2 结果后写的，在 v0.2 原题上复测会高估效果。
